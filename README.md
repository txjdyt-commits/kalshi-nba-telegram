# Kalshi NBA Telegram bot

A hosted Telegram bot that sends one alert per live NBA game when the pregame favorite's Kalshi bid/ask midpoint is **75% or higher**. Your Mac can be switched off after cloud deployment. No trades are placed.

## Activation

1. In Telegram, open the official [@BotFather](https://t.me/BotFather), send `/newbot`, and follow its prompts. Keep the resulting bot token private.
2. Put the files in this folder at the root of a private Git repository that Render can access. The included `render.yaml` defines one continuously running Python background worker, the smallest listed worker compute plan, and a 1 GB persistent disk. Hosting and disk incur Render charges; review the deployment plan and current prices before approving it.
3. Create a Render Blueprint from that repository. Enter the BotFather token as the secret environment variable `TELEGRAM_BOT_TOKEN` in Render. Do not commit it to the repository or paste it into chat. The Blueprint generates a random `PAIRING_CODE`.
4. Once deployed, copy `PAIRING_CODE` from the worker's Render Environment settings. In a **private chat with your new bot**, send `/start YOUR_PAIRING_CODE`.
5. Wait for the pairing confirmation, then send `/test` and `/status`. A recent successful scan plus a received test message verifies the essential pieces. Enable Telegram notifications on your phone.

This package is deployment-ready source, not proof of an active deployment. Monitoring starts only after the cloud worker is running with its token configured. Telegram hosts the chat interface; Render hosts the polling process.

## Telegram commands

| Command | What it does |
| --- | --- |
| `/start PAIRING_CODE` | Pair the first private chat using the secret code |
| `/status` | Show alert state, threshold, last successful scan, and recent scan issue |
| `/pause` or `/stop` | Pause alert delivery |
| `/resume` | Resume delivery for currently qualifying games |
| `/test` | Send a test reply |
| `/help` | List commands |

Pairing is persisted and cannot be replaced by another Telegram user. Other users and group chats are ignored. Pause/resume state and update offsets survive worker restarts. A dedicated new bot is recommended; an existing webhook is detected and left unchanged.

## Alert rules

- Match NBA winner markets (`KXNBAGAME`) to ESPN's live scoreboard using both teams and Eastern game date.
- The **pregame favorite** means the unique favorite in the last valid pregame snapshot, not the team favored when the market first opened. On midgame startup, recover the latest common one-minute candle for both teams strictly before scheduled tipoff, within 30 minutes. Missing/invalid history or tied prices means skip the game.
- Alert only for a game reported in progress, at halftime, or between periods. Skip finished, delayed, postponed, cancelled, ambiguous, and unmatched games.
- Compare the unrounded YES quote midpoint `(bid + ask) / 2` against 0.75. A 74/76 quote qualifies; 74/75 is 74.5% and does not. This can differ from Kalshi's display or last trade and is not an independently estimated win probability.
- Skip missing, crossed, zero/100%, or quotes with a spread wider than 10 cents.
- One automatic delivery attempt per game, persisted on disk. Starting while a live favorite is already above 75% also qualifies. No repeated alerts when it crosses back and forth.
- Target 30-second scans; network time and retries can lengthen this. Brief threshold touches can be missed. ESPN's publicly accessible feed has no supported developer API stability guarantee, and provider delays can occur.

## Hosting and persistence

Use one worker instance with `STATE_DIR` on the mounted persistent disk. The disk stores `alerts.sqlite3` and `telegram.sqlite3`. Do not delete the disk or deploy multiple copies: doing so removes pairing/duplicate state or creates duplicate bot pollers. A process lock prevents two instances using the same state directory. No public web server or browser tab is required. SIGTERM/SIGINT stop new cycles; in-flight HTTP operations finish or time out.

Environment variables:

| Variable | Value |
| --- | --- |
| `TELEGRAM_BOT_TOKEN` | Private token from BotFather, entered in hosting secrets |
| `PAIRING_CODE` | Random secret generated by Render; at least 16 characters |
| `STATE_DIR` | `/var/data/nba-alerts` for the Blueprint |
| `THRESHOLD` | `0.75` |
| `POLL_SECONDS` | `30` |
| `MAX_SPREAD` | `0.10` by default |

Docker is also supported with a persistent volume at `/data` and the same environment variables. Python 3.9+ is required; the supplied Render configuration uses Python 3.12. All runtime dependencies are from the standard library.

## Failures and delivery semantics

Telegram credentials are kept out of exception logs. API failures back off; known Telegram rate limits defer a message without consuming the game alert. Pausing also does not consume an alert.

Before sending, the bot records an attempt. A crash or ambiguous Telegram response leaves an `attempting`/`uncertain` record, preventing automatic duplicate sends. This is at most one automatic attempt, not a guarantee of receipt. Telegram's accepted response does not prove a phone notification was displayed.

Stop the worker before using these maintenance commands in its environment with its persistent disk:

```sh
python bot.py --status
python bot.py --retry-alert GAME_ID
```

Only clear an uncertain attempt after checking your Telegram history. Restart the worker afterward; a cleared game alerts only if it is still live and qualifies. `/status` reports scan health; host logs and `--status` provide individual delivery-attempt details.

## Checks

```sh
python -m unittest -v
python bot.py --dry-run --once
```

Dry run needs no Telegram token, sends nothing, and uses a separate preview database. Tests cover threshold logic, live-state filtering, original-favorite preservation, historical cutoff, exact matching, restart duplicate protection, private pairing, unauthorized commands, pause/resume, rate limits, secret-safe errors, and uncertain responses.
